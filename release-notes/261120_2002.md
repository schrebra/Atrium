Atrium 261120_2002 (schema v17): faster builds, and a CI pipeline that
runs the full battery only when it matters.

- Builds are faster. The installer's three B1 publishes (server,
  client, shell) are independent, so they now run concurrently
  through a checked parallel runner: the compile stage costs roughly
  the slowest publish instead of the sum of the three, every exit
  code is still checked, and each command's output lands in the run
  log in order. The Deploy health poll also resolves faster (30
  one-second polls instead of 15 two-second ones; same 30-second
  budget). In CI, the pinned toolchain and downloads (the .NET SDK,
  WiX, the NuGet cache, the PostgreSQL and hosting-bundle
  installers, Chrome for Testing) are cached between runs and the
  deploy job reuses the bundle the build job produced instead of
  building a second time; every restored artifact is still verified
  against its pin, so a stale cache fails loud rather than passing
  silently.
- The full CI battery now runs only on installer, config, or
  workflow changes. The full workflow's push trigger carries a
  paths filter, and a new lightweight workflow (docs-check.yml)
  carries the same three patterns as paths-ignore, so documentation
  and test pushes run only the CI gate instead of queuing behind
  full builds. A push that touches both sets runs both workflows,
  and every push runs at least one of them.
- Release descriptions now come from the repository. A build ships
  its notes as release-notes/<stamp>.md, and the publish job uses
  that file as the release body when it creates the release. A
  release that already exists is never modified, and a build with
  no notes file falls back to the previous default body. This
  release's description is the first one published that way.
- One CI gate runs the repository checks together. tests/ci-gate.ps1
  runs the contract check and the WAL archive-command regression
  test as a single gate with a per-check summary, and it is the
  first step of every CI job in both workflows, so a broken
  contract fails in seconds with the contract named. The contract
  check also grew teeth for the new shape: it now validates the
  paths filter, the gate invocations, the caching, the
  release-notes lookup, and the docs-check partition (28 checks,
  up from 19).
- No application changes and no schema change in this build; the
  embedded server, client, and shell sources are byte-identical to
  261120_1912, and the WAL archiving and Stage 0 prerequisite fixes
  from 261120_1912 are carried over untouched.
