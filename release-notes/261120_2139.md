Atrium 261120_2139 (schema v17): Deploy and CI run faster. No
application changes.

- Deploy Stage 3 installs PostgreSQL and the ASP.NET Core hosting
  bundle in parallel. The two vendor installers are independent
  (different products, different target directories, no shared
  inputs) and were the two longest waits in Deploy, run back to
  back: 136s and 259s measured on the CI runner on Nov 20, 2026.
  They now run as one batch, so Deploy pays roughly the slower
  install instead of the sum. Stage 4 no longer installs the
  bundle; it verifies the install landed (the ASP.NET Core Module
  V2 file) before configuring IIS, and its /health proof still
  closes the stage. Exit-code acceptance is unchanged from the
  serial calls.
- The first base backup in Stage 3 passes --checkpoint=fast to
  pg_basebackup. Without it the backup waits for the next scheduled
  checkpoint before streaming; that wait measured 112s on a 33 MB
  database, nearly all of it idle.
- The Deploy smoke test moves out of the per-push workflow into a
  new nightly workflow, deploy-nightly.yml. It runs at 09:00 UTC
  when the day changed main (a preflight job compares the last
  successful nightly run's commit with the current HEAD and skips
  unchanged nights) and always runs on manual dispatch. Deploy was
  10m 37s of the 12m 45s push-run wall clock; a push run is now
  the build, the two runtime smoke tests, and the release job.
  Releases are unaffected: the release job never needed Deploy.
- The Windows CI jobs exclude the workspace (and, where relevant,
  the PostgreSQL and Atrium install paths) from Defender real-time
  scanning. The runner is ephemeral and everything scanned there
  was just checked out or just built. The product installer is
  untouched: its Stage 0 Defender precondition still runs on real
  servers exactly as before.
- The Windows runtime smoke test provisions PostgreSQL from the
  official EDB binaries ZIP instead of the EDB installer: the ZIP
  is verified against a recorded SHA-256, extracted to the same
  directory the installer used, and a cluster is created with
  initdb and started with pg_ctl. That step measured 2m 58s of
  the job's 4m 24s. The shipped bundle still carries the EDB
  installer; Deploy on a real server is unchanged.
- The contract check grows from 31 to 44 checks, covering the
  parallel installer batch, the fast checkpoint, the Stage 4
  verification, the ZIP provisioning, the Defender exclusions,
  and the nightly workflow's shape and guard.
- No application changes and no schema change in this build; the
  embedded server, client, and shell sources are byte-identical
  to 261120_2022.
