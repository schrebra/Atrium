Atrium 261120_2022 (schema v17): the WiX pin moves to the v5 line. No
application changes.

- WiX is pinned to 5.0.2, down from 7.0.1. The Open Source
  Maintenance Fee EULA applies to the WiX v6 and later binaries
  only, so the v5 line builds the shell MSI with no fee and no EULA
  acceptance: the installer's wix build call no longer passes
  --acceptEula wix7, because there is no EULA to accept. The pin is
  updated in the config template (WixVersion), in CI, and in the
  README's pinned-versions list. The shell MSI source uses the WiX
  v4 language, which v5 compiles unchanged, and the produced MSI is
  the same standard Windows Installer package.
- The trade is stated plainly: the v5 line is out of community
  support (consumer security fixes ended in February 2026). That is
  accepted deliberately. WiX runs only at build time on the build
  machine, and the pin can move to a current line later if the fee
  position is ever accepted instead. This settles the WiX licensing
  question raised in issue #91.
- The contract check grows from 28 to 31 checks: the WiX pin must
  be a v5 release, the CI install must match the config pin, and
  the installer must not contain a EULA acceptance argument.
- No application changes and no schema change in this build; the
  embedded server, client, and shell sources are byte-identical to
  261120_2002, and the 261120_1912 WAL archiving and Stage 0 fixes
  and the 261120_2002 pipeline changes carry over untouched.
