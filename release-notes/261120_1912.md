Atrium 261120_1912 (schema v17): WAL archiving fix, and backup prerequisites
checked before teardown.

- WAL archiving now delivers, and Deploy proves it. Every published build
  up to and including 261120_1820 ships the broken archive_command, so no
  published build delivers WAL to the off-VM target; this build is the
  first that does, and Deploy now proves delivery. The command written to
  postgresql.conf now has every backslash doubled (PostgreSQL's config
  parser was consuming single backslashes as escapes, mangling the target
  path while the archiver exited 0) and an "if not exist" guard, so a
  retried archive does not recopy a segment that already arrived. Stage 3
  reads the setting back after the restart and fails unless SHOW
  archive_command returns exactly the intended command; it then forces a
  WAL segment and fails unless pg_stat_archiver records it archived with
  zero failures and the segment file is present at WalArchivePath. The
  failure message names the permission the PostgreSQL service account
  needs on the target share. A regression test
  (tests/archive-command-check.ps1) round-trips the written string through
  PostgreSQL's own parser for a local path and a UNC path.
- Archive and backup targets are validated in Stage 0 preflight, before
  Stage 1 teardown destroys the previous deployment (a bad target used to
  be discovered only in Stage 3, after the destruction). In production
  both targets must now be UNC paths, must not resolve to this machine
  (localhost, loopback addresses, and the server's own name or FQDN are
  rejected), must exist, and must accept a write, proven by a probe file
  that is created and deleted. Lab mode keeps the existence and
  writability probes and skips the UNC rule, since lab targets are local
  by design. The admin guide (§9.2) now states the related permission
  requirement: the targets must grant write access to the PostgreSQL
  service account, which for a UNC target means the server's machine
  account.
- No application changes and no schema change in this build; the embedded
  server, client, and shell sources are byte-identical to 261120_1820.
